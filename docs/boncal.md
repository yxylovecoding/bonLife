# bonCal 模块边界

bonCal 是现有项目的内部模块，不是独立应用。账号、Turso 存储、Render 服务、Cloudflare Cron 与队列均沿用现有部署。

## 读取与修改

- `src/boncal` 负责分类、北京时间日期边界、场景、城市候选、分段、标题、来源修复和前端投影。旧 `utils` 路径仅兼容转出，不能继续实现另一套规则。
- `api/_bonCal/provider.ts` 是 Outlook 与 Google 读取入口；`repository.ts` 管理公共存储、版本和写锁；`service.ts` 提供上下文、排程和原日程读取。
- `GET /api/outlook-calendar?action=context&startDate=YYYY-MM-DD&endDate=YYYY-MM-DD` 返回 `BonCalContext`：版本、范围、逐日场景及地点、行程、原日程、占用、来源与状态。范围的结束日不包含当天；行程展示的结束日仍是最后一个出游日。
- `PATCH ...?action=context` 接收 `{ revision, data }`；现有 `/api/sync` 使用相同仓储及版本校验，保持原有编辑页面。并发修改返回 409，客户端保留未保存的本地编辑。
- 暂保留 `calendar-tags`、`trip-tags`、`app-config` 键。公共字段由 bonCal 挑选；账单确认、费用、工资及心愿金额属于 BonBills。无版本的旧上传只接受业务字段，不能覆盖公共日历及来源派生字段。
- 衣橱每日地点和行程地点仍保存在原记录中，写入经过 bonCal 公共锁，继续使用记录 CAS 和幂等回执，并更新公共地点版本。穿搭、衣物、场景偏好和历史记录归 BonClothes。
- Orchestrate 全量、小时、显隐、专项调用统一场景与地点；BonLog 只负责任务规则、挑选和执行。天气与衣橱读取同一地点解析。前端离线显示可调用 bonCal 的纯函数，不得自己分类或分段。

## 来源与优先级

沿用连接中「玩」「课」的全天日程分类范围和用户的规则排序；其他订阅保留日程展示与定时占用。学校、家、实习段、手动标记和单日覆盖均由 bonCal 解释。

地点顺序沿用共享解析：显式手动地点／当天有效定位、单日城市覆盖、行程明确地点、学校／家／实习城市及可明确解析的出游目的地。多目的地没有每日明确位置时不能选第一站代替当天位置。排程只使用已有标记或已配置阶段覆盖的日期，不能把日历空白推测为可安排日期。地点或标签读取失败保留受影响安排。衣橱不再用浏览器上一次城市自动补地点；定位仅在当天使用，未来日期通过明确选择地点保存。

法定工休的节假日结果由 bonCal 服务端读取并保存为公共派生字段，与日期场景共同纳入版本；旧客户端不能覆盖。前端日期投影、排程及天气均使用这一份结果，工资计算继续属于 BonBills。

## 生日与旧数据

生日（中文“生日”、英文 birthday／bday、🎂）、节日提醒、月经／🩸和忽略事项不会贡献出游日期、目的地、标题或自动出游心愿。忽略名单过旧不能放过生日。同日真实旅行、回家、实习独立参与原有优先级。原生日日程仍展示，定时活动继续占用原时段。

同步读取和 context 读取会运行幂等修复。明确的旧生日标题、混合标题及来源关联可撤销错误出游并恢复原场景；不因历史事件退出订阅窗口删除历史。首次修改前保存账号内恢复副本 `boncal:repair:reminders:v1`。旧快照重放同样经过当前分类清理。

无人工内容的自动心愿可清理；含金额、明细、人工期限等内容则保留并解除错误行程关联。衣橱旧搭配与计划保留，错误生日行程退出有效行程列表。待办依据保存的实例 ID 核对，只有完整任务树仍与自动结果相符且没有用户新增子任务、编辑、重复设置变化或完成记录时才清理；其余保留并退出出游管理。

## Google 备用

已存在的 Google 导入订阅是备用来源。仅绑定同名且唯一的 `@import.calendar.google.com` 副本；不读取名为 Birthday 的主日历作为出游来源。每次优先读取 Outlook，某个来源失败时单独尝试该来源的 Google 副本，下次 Outlook 恢复后自动回到主源。Google 订阅刷新有延迟，因此备用读不到的旧行程或完成记录保留，不能认定取消。两个来源都失败时保留已有结果并报告错误。

Google 复用现有 Apps Script 只读桥接，四份订阅的 ID 固定在脚本属性中，调用方不能扩展日历范围。Google 授权保存在 Google；现有服务仅加密保存桥接地址和访问密钥。所有分页完整、日期范围与请求 ID 一致后才接受结果；连接变更后的在途读取不能更新状态。连接操作沿用 `GET/PUT/DELETE /api/outlook-calendar?app=google` 与现有 Orchestrator 入口，配置和部署见 [Google 备用接入](google-calendar-fallback.md)。不新增 OAuth 客户端、云项目、定时任务或付费服务。

## 验证与守卫

`scripts/check-boncal-boundary.mjs` 随部署构建执行，禁止业务代码定义公共分类／分段／地点函数或绕过模块抓取 Outlook、读写公共键。测试覆盖生日、真实出游重叠、历史恢复、旧上传保护、CAS、Google 回退、分页、请求核验及断开竞态。上线按 API 回读上下文；涉及排程先读取同轮 `plan-details`，再核对 TickTick 原始任务，保留任务标签、实际完成及人工编辑。
